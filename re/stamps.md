# Метки времени записи (своё, у оригинала нет)

Зачем: подпись оригинала (`signature=`, MD5 с открытой «солью» `TypingStatistics`) — контрольная сумма, а не
доказательство: файл правится и подпись пересчитывается за секунду. Метки времени делают так, что **автор не может
выдать правленую, сгенерированную или «ускоренную» запись за настоящий набор**, если писал её официальной программой.

## Что доказывается и что нет

- Доказывается: записи существовали в момент метки и **после неё не менялись**; время между метками сходится с
  `dt` записей, т. е. запись **набрана в реальном времени** (до допуска `kToleranceMs` = 2,5 с на полосу, см. ниже);
  сколько нажатий ОС пометила как искусственные (`Injected`, 0x1000: SendInput, uinput, CGEventPost).
- Не доказывается: что набирал человек. Изменённая программа (код открыт) может «набирать» сгенерированное в реальном
  времени и брать на это метки; аппаратный эмулятор клавиатуры для ОС неотличим. Это предел любой проверки на
  компьютере автора — тот же уровень, что у сайтов-тренажёров.

## Проверка токена (`src/core/TimeStamp`, без OpenSSL)

ContentInfo → SignedData (ровно один SignerInfo) → eContent = TSTInfo. Подписанные атрибуты: `contentType` =
id-ct-TSTInfo, `messageDigest` = хэш TSTInfo алгоритмом SignerInfo. Подпись RSASSA-PKCS1-v1_5 (SHA-256/384/512; SHA-1
не принимается) над DER атрибутов с тегом SET. Подписант ищется по issuer+serial или SubjectKeyIdentifier среди
сертификатов токена и файла. Цепочка: у подписанта — EKU timeStamping; у промежуточных — `cA`; все действительны на
момент `genTime`; цепочка доходит до сертификата с закреплённым ключом или до сертификата, подписанного закреплённым
ключом. Отзыв (CRL/OCSP) не проверяется. Разбор DER — `src/core/Der`, RSA (Монтгомери, 32-битные слова) — `src/core/Rsa`.
Проверки подписей кэшируются (метки одной записи делят цепочку), подготовка Монтгомери (R² mod n) — по модулю ключа. Release, Windows: метка без кэша — 4,9 мс (было 11,8 без кэша модулей; ~3 операции RSA-4096), новая метка при общей цепочке — одна операция (~1,5 мс: час набора, ~360 меток, — ~0,5 с при открытии); отчёт по проверенным меткам на 176 записях — 0,65 мс. Независимая сверка: `openssl ts -verify -digest <хэш>
-in <токен> -token_in -CAfile <три корня> -partial_chain` — OK на всех golden-метках.

## Цепочка (`src/core/Stamps`)

Хэшируется **нормализованный** поток записей (`Recalc::Normalizer` — тот же, что у `Recalc::normalized`): судьба записи
(оставить / выбросить автоповтор модификатора) и её `dt` решаются при её приходе и не меняются потом. Поэтому «Пометить»,
метки и прочие правки, которые нормализуют документ, цепочку не ломают.

Запись кодируется 12 байтами: `dt`, `flags & ~(0x100 | 0x200 | 0x40000000)` (временные и ставящиеся потом пометки),
`ch` — u32 LE. Метка i покрывает записи `[end(i−1), end(i))`, её хэш:

```
SHA-256("TypingStatistics stamps 1" ‖ u8 len(prev) ‖ prev ‖ u32 (end(i) − end(i−1)) ‖ u32 delayMs ‖ записи)
```

`prev` — хэш (imprint) предыдущей метки, как он подписан в её токене (пусто у первой); `delayMs` — сколько прошло от
последней покрытой записи до отправки запроса (мерит программа при отправке; под хэшем, т. е. потом не правится).
Длина вместо абсолютной позиции: после удаления в начале записи границы следующих меток переносятся, и они продолжают
сходиться.

**Когда метка** (`StampRecorder`): первое нажатие сессии записи (после включения «Вкл», открытия, очистки); первое
нажатие через `kIntervalMs` = 10 с набора после последней заверенной записи; через `kIdleMs` = 2 с после последнего
нажатия; при выключении записи. Пока запрос в пути, новых нет. Неудача службы — сразу следующая служба новым запросом
(своя задержка); все три не ответили — повтор через 5 с, ошибка видна на кнопке. Ответ к прежнему документу или до
правки (поколение) отбрасывается. Сертификаты запрашиваются всегда (`certReq`), в файл кладутся один раз.

## Проверка записи (`Stamps::verify`)

- Метка **годна**, если её токен проверяется, imprint — SHA-256 и равен хэшу её куска. Концы меток должны расти и не
  выходить за записи, иначе эта и все следующие — плохие.
- **Время.** Для годной метки `offset = genTime − (время её последней записи по dt) − delayMs`. У честной записи
  `offset` ≈ задержка сети + отбрасывание долей секунды и почти постоянен, какие бы ни были паузы. Подряд идущие годные
  метки с разбросом `offset` не больше `kToleranceMs` образуют полосу; записи между соседними метками полосы (включая
  последнюю запись предыдущей) — **время подтверждено**. Плохая или аннулированная метка рвёт полосу. Обмануть время
  внутри полосы можно не больше чем на допуск (2,5 с) — разброс считается от всей полосы, а не от пары.
- **Аннулированная** метка (флаг 1 в строке файла): программа сама помечает так метки, чьи записи изменила правка
  (удалить, удалить нетекстовые, преобразовать раскладку) — `Stamps::follow` по `KeyRecord::tag` (номер записи до
  правки; живёт в байтах выравнивания, в файл не пишется). Её токен остаётся звеном цепочки, записи не считаются.
- Итог: `None` (меток нет), `Confirmed` (время подтверждено для всех записей), `Partial` (есть аннулированные или
  незаверенные/неподтверждённые записи), `Broken` (есть плохие метки — правка не этой программой или подлог).
- «Отменить» возвращает и метки. «Сохранить блок» части записи меток не несёт (они покрывают всю запись); блок без
  выделения (вся запись) — несёт.

## Файл

Строки заголовка (оригинал незнакомые строки пропускает, подпись MD5 их не включает; строкой данных их не примет ни
порт, ни оригинал — она должна начинаться с шестнадцатеричного числа):

```
Stamp<i>=<end> <delayMs> <флаги: 1 = аннулирована> <токен без сертификатов, base64>
StampCert<i>=<сертификат службы, DER, base64>
```

Токен без сертификатов — 0,8–1,5 КБ (метка раз в 10 с набора: ~0,5 МБ на час); сертификаты — один раз на файл.
Токен с сертификатами (как его даёт служба) тоже читается — так пишет `make_stamped.py`.

## Интерфейс

- Настройки (Form8): «Заверять запись метками времени (нужен интернет)», ключ `StampRecording` (корень настроек, не
  пресет), по умолчанию выкл.
- Кнопка в тулбаре слева от кнопки темы (видна, если метки в документе есть или заверение включено):
  «Метки» (серая, меток ещё нет), «✓ 100 %» (зелёная), «✓ N %» (жёлтая: время подтверждено для N % записей), «✗» (красная);
  « !» — последняя попытка не удалась (подсказка — причина). Щелчок — окно с подробностями (`showProof`).
- `tsstat --verify file.tsf` — отчёт строками «ключ\tзначение», код выхода 0 / 1 / 2 (подтверждено / не всё / плохие).

## Тесты

- `tests/golden/stamps/stamped.tsf`, `compressed.tsf`, `more.tsf` (Certum, SwissSign, Microsoft) —
  `re/scripts/make_stamped.py` (своя реализация хэша на Python,
  метки настоящих служб, записи «набираются» по часам; `--compress 0.85` — записи утверждают набор на 15 % быстрее
  настоящего). Программа их принимает → обе реализации понимают формат одинаково.
- `tst_stamps`: DER, запрос, токены (подпись, время, без сертификатов), RSA, отчёт, сжатое время → `Partial`, подмены
  (`dt`, символ, удалённая/переставленная метка, задержка) → `Broken`, пометки → `Confirmed`, правка + `follow`,
  живая цепочка = imprint токенов.
- `tst_ui`: `stampRecorder` (подменённая сеть: когда метка, переход к другой службе, отброшенный ответ, метка простоя),
  `proofButton` (кнопка на golden, удаление → аннулирована, отмена), `stampLive` (настоящие службы через сетевой код
  программы, только с `TS_STAMP_LIVE=1`, ~15 с).
