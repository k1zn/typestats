# Веб-камера (своё, у оригинала нет)

Сделано 2026-10-07 (план `C:\Users\kizn\.claude\plans\rosy-popping-wren.md`); на живой камере не проверено.

Во время набора по желанию пишется веб-камера (и микрофон). Видео лежит внутри `.tsf`, режется вместе с «Сохранить
блок», показывается кадром под клавограммой и воспроизведением, заверяется метками времени вместе с записями.
К прикреплённому видео оригинала (`AttachedVideo`/`VideoTimeShift`, `video.md`) отношения не имеет: те поля
читаются и пишутся как есть.

## Кодеки

- **Видео — AV1, libaom realtime** (режим WebRTC): `AOM_USAGE_REALTIME`, `cpu-used` 10, `lag_in_frames` 0 (кадр
  выходит сразу, B-кадров нет), VBR с потолком, ключевой кадр раз в 4 с (`kf_max_dist`), I420 8 бит. Сборка
  `CONFIG_REALTIME_ONLY=1`, `CONFIG_AV1_HIGHBITDEPTH=0`, `MinSizeRel`, без AVX-512; кодер и декодер в одной библиотеке.
  Один exe с кодеками — 20,7 МБ (без них 17,1); кадр 640×360 кодируется за 1,5 мс.
- **Звук — Opus** (libopus), моно 48 кГц, 16 кбит/с, `OPUS_APPLICATION_VOIP`, пакеты 20 мс. По умолчанию выключен.
- Пресеты:

  | пресет | кадр | к/с | видео, кбит/с |
  |---|---|---|---|
  | Экономно | 320×240 | 10 | 40 |
  | Обычно (умолч.) | 640×360 | 15 | 90 |
  | Хорошо | 640×480 | 24 | 200 |

  В `.tsf` (Z85, +25 %) «Обычно» — ~0,85 МБ/мин, звук — ещё ~0,15.
- Исходники — `FetchContent` с `URL_HASH` (libaom 3.15.1 — подпись AOMedia `B002F08B…0B830498` проверена, opus 1.5.2 —
  SHA-256 с xiph.org). NASM нужен libaom для x86.

## Контейнер (`MediaClip`)

Свой: дописывается по ходу записи, режется и хэшируется по пакетам. Все числа little-endian.

```
"TSMV" u8 version=1
u8 streams; на каждый поток: u8 kind (0 видео, 1 звук) u8 codec (0 AV1, 1 Opus) u16 a u16 b u8 c
        видео: a, b — ширина, высота кадра первой сессии; звук: a — частота / 100, b — каналы
i64 originUs          время документа = pts − originUs (правка и обрезка двигают его, а не pts)
i64 startUs           начало видимой части в шкале pts (после «Сохранить блок»; иначе INT64_MIN — всё видно)
i32 shiftMs           ручная поправка синхронизации: картинка показывается на shiftMs позже своего pts
пакеты до конца:  u8 stream  u8 flags (1 = ключевой)  i64 ptsUs  u32 size  data[size]
```

- **Время документа** `T(i) = Σ dt_j, j = 0..i` по записям документа (`dt` записи 0 — пауза от начала круга
  таймера, т. е. от включения записи): начало записи — 0, пакеты до первого нажатия имеют `T` ≥ 0. Перерывы записи
  (перехват выключен) — разрывы в `pts`.
- Байты пакета (заголовок + данные) не меняются никогда: их хэшируют метки (`stamps.md`). Меняются только поля
  заголовка контейнера.
- Пакеты идут по возрастанию `pts` внутри потока; потоки перемежаются по времени поступления.
- Новая сессия видео начинается ключевым кадром; размер кадра может смениться только на ключевом (AV1 несёт sequence
  header в нём).

## В файле

```
Webcam=1 <байт> <SHA-256 контейнера, hex>   (целостность; подлинность — метки)
WebcamData1=<Z85>         по 65 536 символов на строку
WebcamData2=...
```

Z85 (ZeroMQ RFC 32): 4 байта → 5 символов; длина контейнера дополняется нулями до кратной 4, настоящая — в `Webcam`.

**Имя ключа не должно начинаться с шестнадцатеричной цифры.** Оригинал разбирает каждую строку
`sscanf(line, "%x %s", &dt, buf)` с буфером на стеке: строка `Cam…=…` дала бы `%x` = 0xCA и `%s` длиной в строку
(переполнение). `W`, `S` (`Stamp`), `P` (`Platform`) — не hex: `sscanf` возвращает 0, строка пропускается.
Подпись MD5 строк заголовка не включает. Проверено 2026-10-07 стендом: оригинал открыл `824.tsf` с десятью строками
`WebcamData` по 65 535 символов — не упал, ListView2 и текст совпали с портом (`diffstand.py`).

## Синхронизация

- В сессии записи `dt` записей — разности отметок `hookNowUs` (`Recorder::lap`), поэтому
  `T = T(якорь) + (steady − steady(якоря))`; якорь — начало круга таймера сессии (`T` = сумма `dt` всех записей до
  него).
- Время кадра — отметка устройства в том же домене: V4L2 `V4L2_BUF_FLAG_TIMESTAMP_MONOTONIC` (`CLOCK_MONOTONIC`),
  macOS — host clock `CMSampleBuffer` (`mach_absolute_time`), Windows — `MFSampleExtension_DeviceReferenceSystemTime`
  (QPC, 100 нс); нет её — время прихода.
- Правка: «Удалить» и нормализация отдают время выброшенных записей следующей, `T` оставшихся не меняется. Меняется
  только `T` записи 0 (удалено начало, отброшены ведущие отпускания, у нормализованной записи 0 `dt` = 60 с): после
  правки `delta = T_новое(0) − T_старое(запись, ставшая нулевой)` (по `KeyRecord::tag`), `originUs −= delta`.

## «Сохранить блок»

Записи блока — нормализованные `[from, to)`; в новом файле `T_новое(i) = T(from + i) − T(from) + dt(from)`. Окно видео —
ровно время записей блока, `[T(from), T(to − 1)]` (`MediaClip::cut`), затем `moveOrigin(−dt(from))`: первое нажатие
блока в новом файле — в `T = dt(from)`, там и начинается видимое видео. Видео — от
последнего ключевого кадра с `pts` ≤ начала до последнего кадра ≤ конца; звук — пакеты, пересекающие окно, плюс
80 мс до него. Без перекодирования; `startUs` — начало окна, плеер декодирует преролл и не показывает. Экспорт в
WebM (`Webm::write`) начинается с ключевого кадра.

## Порт: что где

- `src/core/MediaClip`, `Z85`, `WebmWriter`; строки `.tsf` — `TsfFile`; `DocTime` — время документа и модели.
- `src/media`: `Av1Codec` (libaom), `OpusCodec`, `Yuv`, `Capture` (Windows — Media Foundation, загружается при запуске:
  в Windows N его нет без Media Feature Pack; виртуальные камеры — `CaptureDShow`, см. ниже), `AudioOut` (Windows —
  waveOut). macOS и Linux — заглушки (шаг 8).
- **Виртуальные камеры Windows** (OBS Virtual Camera, 2026-10-07): это фильтры DirectShow в категории video input без
  устройства за ними — Media Foundation их не видит. `CaptureDShow` добавляет в список фильтры этой категории без
  свойства `DevicePath` (у настоящих камер оно есть, их перечисляет MF), id — `dshow:` + имя моникёра. Захват: граф
  источник → Sample Grabber (qedit.dll; устарел, но есть в Windows 11) → Null Renderer, без часов графа (кадры не
  ждут времени показа); формат — ближайший к нужному через `IAMStreamConfig`, NV12/I420/YUY2/RGB читаются сами, иное —
  через декодер, который ставит DirectShow. Время кадра — время прихода (виртуальная камера отдаёт кадр, когда делает).
  OBS отдаёт свой размер вывода (здесь 1920×1080), запись уменьшает. `tst_media::virtualCamera` — если такая камера есть.
- `src/ui/WebcamRecorder` — устройства, кодеры в своём потоке, время кадров по таймеру хука (`Recorder::timerUs`:
  `T = Σdt + (s − таймер)` — ровно то время, которое получила бы запись в момент `s`); пакеты до первого события ждут.
  Частота пресета соблюдается отбрасыванием кадров; кодер не успевает — кадр отбрасывается (очередь ≤ 2).
  Размер пресета — рамка: картинка камеры пишется целиком, с её пропорциями (2026-10-08: камера 1920×1080 при 640×480
  писалась серединой 4:3, а предпросмотр показывал кадр целиком; теперь — 640×360). Размер видеопотока задаёт первый
  кадр сессии (`WebcamRecorder::fit`, кодер открывается им), кадры иных пропорций потом обрезаются под него.
- **Когда пишет камера** (2026-10-07): с первой клавиши, набранной в этот документ при «Вкл» (`keyEvent`), до «Выкл»,
  открытия другого файла или очистки (`setDocument`). Файл, открытый только посмотреть, в видео не пишется. Камера
  запускается до секунды и ещё подстраивает экспозицию (2026-10-08: видео начиналось с чёрного, первые клавиши уже
  набраны), поэтому она открыта заранее — пока ждёт первую клавишу (`WebcamRecorder::setArmed`: хук запущен, «Вкл», запись
  камеры не остановлена; индикаторы камеры и микрофона горят всё это время), и запись начинается с её последнего кадра
  перед клавишей (не старше секунды) и последних 0,3 с звука (звук самой клавиши может начаться в буфере, пришедшем до
  неё).
- **Кнопка камеры** — в углу тулбара, под кнопкой меток (кнопки 20/21 оригинала выключены, его AVI не перенесён):
  щелчок — окно видео, ▾ — меню «Записывать камеру при наборе», «Записывать звук», «Свойства камеры…», «Сохранить
  видео в WebM…». Вид: идёт запись — красная, с красной точкой и длиной записи; в документе есть видео — зелёная, с
  длиной; иначе — одна камера (тусклая, когда запись выключена). `MainWindow::updateCameraButton`.
- `src/ui/VideoWindow`: во время записи — картинка камеры; иначе — кадр левого края клавограммы (или «в записи нет
  видео»); ▶ — клавограмма прокручивается в реальном времени, звук — через `AudioOut`; ползунок перемотки (щелчок по
  полосе — туда, стрелки — секунда, перетаскивание при воспроизведении ставит его на паузу); 💾 — WebM. В сжатой паузе
